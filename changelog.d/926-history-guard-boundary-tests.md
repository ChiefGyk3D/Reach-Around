- Instance template: offline checks of shipped CODEOWNERS pattern coverage and change detectors for the guard workflow (#926, follow-up to #619). A test reads the shipped `.github/CODEOWNERS` with segment-aware matching after GitHub's CODEOWNERS page (`*` does not cross `/`, last match wins, empty owner un-owns, unsupported syntax refused) and checks that every guard file, workflow file and base-commit file the guard runs matches a rule with an owner while the history file and `numbers.json` match none, with conformance fixtures and a coverage check that is itself mutation-tested. It does not show that GitHub enforces anything: enforcement is shown only by the owner's live gates (the checklist and G1 in the template README), and activation stays blocked until they are observed. The README also gains an inventory of every input name the workflow and script read. Tests pin every workflow step, the workflow file itself byte for byte, and every file the job runs (the guard script and two shell scripts) by SHA-256 with exact repository-relative path matching, list every other file checked out from the base commit with the reason it is not executed, reject unexpected jobs, and run a best-effort scan for network commands. These are change detectors and a heuristic, a review trigger rather than an independent check (the engine's CODEOWNERS owns the test file so updating the table needs the maintainer's review), and they cannot show the absence of network use; runtime egress confinement is a separate follow-up. The trust step runs under the shell form Actions uses on a real sparse tree, and the release-mismatch test always runs with a pure-python jq stand-in. No workflow or activation behavior changed.
