- Instance template: offline checks of shipped CODEOWNERS pattern coverage and change detectors for the guard workflow (#926, follow-up to #619). A test reads the shipped `.github/CODEOWNERS` with segment-aware matching after GitHub's CODEOWNERS page (`*` does not cross `/`, last match wins, empty owner un-owns, unsupported syntax refused) and checks that the guard paths it names match a rule with an owner while the history file and `numbers.json` match none, with conformance fixtures and a mutation-tested coverage check. It does not show that GitHub enforces anything: enforcement is shown only by the owner's live gates (the checklist and G1 in the template README), and activation stays blocked until they are observed. The template README gains an inventory of the input names the test's parsers find in the workflow and script, a CLAIMS table that maps each claim to the tests that back it, and a KNOWN GAPS list (callees of callees, extensionless scripts, paths built at run time, implicit process inputs such as PATH and tool configuration, network use). Tests pin the workflow file byte for byte, each workflow step and the three scripts the steps name by SHA-256, list the other base-commit files with the reason they are not run, fail on a script callee that is not pinned or on dynamic execution in a pinned script (naming the line), reject unexpected jobs, and run a best-effort scan for network commands. These are change detectors and a heuristic, a review trigger rather than an independent check (the engine's CODEOWNERS owns the test file), and they cannot show the absence of network use; runtime egress confinement is a separate follow-up. The trust step runs under the shell form Actions uses on a real sparse tree, and the release-mismatch test always runs with a pure-python jq stand-in. No workflow or activation behavior changed.
