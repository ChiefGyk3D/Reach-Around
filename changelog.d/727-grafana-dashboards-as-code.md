- Example Grafana dashboards as code (#727): `examples/grafana/` holds a provisioned read-only SQLite data source (`frser-sqlite-datasource` 4.0.6, `mode=ro`, no secret), a dashboard provider, and three dashboards: counts over time (likely-human views and link clicks per day, traffic classes, clicks per 100 views, collection gaps, cutover marker), link clicks by link (printed rows only), and Twitch and Kick side by side (one function builds both sides, and a test fails if they differ). Counts of 1 to 4 read Under 5 on stat panels; the merged `(below the floor)` row is labeled as merged. Dark is the default theme. A synthetic sample generator (`sample/make_sample_export.py`, fixed seed, example creator) feeds the real `grafana-export` so the dashboards render before any live data exists. A rootless Podman recipe (quadlet: own network, own named volume, `127.0.0.1:3737`, image pinned by digest, read-only root file system, no Docker socket, admin password as a Podman secret stored with no trailing newline) runs a separate Grafana. Not in the dashboards because the store does not carry them: clicks by group (#678), link versus icon clicks, the kit funnel and follower counts over time. `tests/test_grafana_dashboards.py` parses the JSON, checks the panels, runs every query against a store built from the sample, scans for secrets, hosts, callsigns and grid squares (with planted negative cases), and checks the Podman recipe. No engine code changed. Docs: `examples/grafana/README.md`, `docs/grafana.md`.
