- Page-view location (#778): a raw view record now holds at most the region and never a city. The default `GEO_LEVEL` is `region` (it was `city`). At level `city` (set knowingly, globally or per site) the Worker adds each view to a daily city counter (`view_city_daily`, new migration 0019) that carries no page, source, device or time of day; the rollup applies the existing small-count floor (five views, or `MIN_CELL` if larger) and folds smaller cities into their region, so reports and exports show city rows only above the floor. The counter is purged with the raw rows. New config key `analytics.geo_level` (default `region`) drives the generated privacy page, which states which level applies and, at `city`, that city totals follow the view records' deletion schedule (visitor-facing wording marked TODO-copy). The write-budget model adds one row per view only when a site is at city (6.6 rows per view, 7.6 with `BEACON_MODE` on); the default 22,700 a day is unchanged. Docs: `docs/deploy.md`, `docs/privacy.md`, `docs/config.md`.
