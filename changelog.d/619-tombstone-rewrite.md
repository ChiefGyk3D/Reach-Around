- Instance template: a labeled, tombstone-only rewrite of the counts history is now accepted, and every other rewrite is refused (#619, epic #364, follows #586). New engine command `counts history-compare` (exit 0 append-only, exit 10 valid rewrite, anything else a refusal; counts only in its output) checks the exact bytes: only `api` records may become tombstones (their corrections go with them), every kept line keeps its content and order, no tombstone is removed or turned back into data, later lines are re-chained and canonical, at most 500 records and 10 percent per rewrite, and every tombstone field and one committed manifest are derived from the redacted keys, a closed reason code and two dates, so a redacted value has no field to hide in; the matching `numbers.json` entry must be removed in the same change. `counts history-redact --derived` writes those forms and the manifest. New instance workflow `history-guard.yml` (one job, check name `History guard`, read-only token, `pull_request` only) reads its scripts and `.github/history-approvers` from the base commit and accepts a rewrite only with the `history-tombstone` label applied by a listed login at least 24 hours earlier, from a `redact/` branch in the same repository, with no open bot refresh pull request, exact allowed paths, a head that contains the current `main`, and the label state read twice. Documented in the instance template README and `docs/social-history.md`. The design gates that need a live GitHub test repository (G1, G2, G4 to G6) are not yet run; see the spec.
