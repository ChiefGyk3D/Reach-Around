- Media kit leads move to their own D1 database (#772, epic #365): leads and kit events are stored and purged only through a new `LEADS_DB` binding, with their own migration folder (`worker/leads-migrations`), so leads have separate access, backup and erasure from analytics. A missing `LEADS_DB`, one that is not a D1 binding, or one that is the analytics database makes the gate and the view route refuse (the usual retry redirect, nothing stored) and makes the hourly job skip the lead purge with one closed log line; there is no fallback to the analytics database. The binding is only a commented block in `worker/wrangler.toml`, so no deploy creates the database early; `docs/deploy.md` says how to create it. `scripts/backup-d1.sh` now prints the database it acts on and refuses a name containing "leads". CI checks the leads migrations with no pre-rule exemption.
