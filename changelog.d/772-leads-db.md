- Media kit leads move to their own D1 database (#772, epic #365): leads and kit events are stored and purged only through a new `LEADS_DB` binding, with their own migration folder (`worker/leads-migrations`), so leads have separate access, backup and erasure from analytics. Every lead path (the gate, the view route and the lead purge, including a direct call to `purgeExpiredLeads`) goes through one proof in `src/kit/separation.ts` and refuses, with nothing stored and one closed log line, unless the two bindings are different databases by what each database states it is (a `db_identity` row written by its own migrations, because a D1 binding exposes no database id) and the analytics database holds no lead rows. Installations that already collected leads run the one-time, dry-run-first `scripts/move-legacy-leads.py` (copy, read back, then delete only the rows it read back, each by id and every column; a row added after the copy survives and is reported); `docs/deploy.md` has the steps. An approval is never remembered (only a refusal, for 10 seconds): the gate proves it at most twice, after its limiters, the view route once before its lead read, the purge once, and the early configuration check makes no D1 query. An ordered cutover (`--freeze`, the move, `--verify`) makes the analytics lead tables refuse inserts at the database so an older Worker cannot store a lead there; it is a required step before the gate is enabled. There is no fallback to the analytics database. The binding is only a commented block in `worker/wrangler.toml`, so no deploy creates the database early; `docs/deploy.md` says how to create it. `scripts/backup-d1.sh` with `--apply` now reads the database's own identity and refuses anything that does not say `analytics`, whatever it is called. The lead purge guarantee now starts at `QUERY_BUDGET` 12 (was 9) because the proof takes up to 3 queries. CI checks the leads migrations with no pre-rule exemption, migration number 0000 included. Cutover freeze check: `scripts/move-legacy-leads.py --freeze` and `--verify` now compare the exact text of the freeze triggers instead of trusting their names, so a same-name look-alike trigger no longer passes for the freeze and the script fails closed. A local file or process error now prints one fixed message, never a traceback. New tests plant hostile same-name triggers and a missing wrangler path. Round 6: `scripts/move-legacy-leads.py` now takes exactly one of `--copy`, `--purge`, `--freeze`, `--verify` (a combination used to run one mode silently with exit 0; it is now a usage error, exit 2, before any write); `scripts/backup-d1.sh` no longer refuses a database by a "leads" substring in its name, only by the identity the database states.
