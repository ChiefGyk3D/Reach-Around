- The D1 backup script now keeps an inventory of the tables it expects, each with the migration that creates it (#932). It reads which migrations the database has applied: a table whose migration is applied must exist, or the run fails with the table name and exit 1 instead of ending in a successful but incomplete backup; a table whose migration is not applied is skipped with a notice. If the applied migrations cannot be read, the run fails. The two aggregate tables `view_hour_daily` and `view_city_daily` are now exported too (they were silently omitted before). A listed table name that contains a line break is refused. The script needs bash 4.0 or newer and says so. Tests derive the inventory from the migrations and fail when it drifts. A table that exists in the database but is not in the script's inventory (from a newer migration, or made by hand) now fails the run before any export, naming it; only SQLite's own `sqlite_*` tables and the reserved `_cf_KV` are accepted without an export. Every table that exists is exported whatever the migration record says: the record only decides whether a missing table is an error, and a recorded name the script does not know is reported as a notice. With no migration recorded, every expected table is required. The bash version guard now runs first, in POSIX syntax. The post-deploy smoke script matches the content-type and nosniff headers without a pipe into `grep -q` (which can lose a race with SIGPIPE under pipefail) and without a bash 4 expansion.
