- The D1 backup script now checks that an export is complete and that the database did not change under it (#944). After each export its file is loaded into a scratch in-memory SQLite database and its row count must lie between the counts taken from the database before and after the exports, so an export that ends early fails the run instead of producing a short backup. The table listing now also carries each table's definition and is taken again after the exports: a table that was dropped, added or replaced during the run fails it. A listing or count answer is trusted only when it is exactly one successful result, never an error object, several results or a failed result. The backup script's note on the ignored `_cf_KV` table now says what ignoring it means. The post-deploy smoke script now requires the content type to be exactly `text/html` (parameters allowed) and the nosniff header value to be exactly `nosniff`; values that only contain those words no longer pass.
