- The D1 backup script now checks that an export is complete and that the database did not change under it (#944). Every table's row count must be the same before and after the exports (a write during the run fails it: rerun, ideally with the write routes paused), and each export file's rows, counted by reading it line by line with size limits and without executing anything in it, must equal that count, so an export that ends early fails the run instead of producing a short backup. A write that replaces rows and leaves every count equal is a documented residual. The table listing now also carries each table's definition and is taken again after the exports: a table that was dropped, added or replaced during the run fails it. A listing or count answer is trusted only when it is exactly one successful result, never an error object, several results or a failed result. The backup script's note on the ignored `_cf_KV` table now says what ignoring it means. The post-deploy smoke script now requires the content type to be exactly `text/html` (parameters allowed) and the nosniff header value to be exactly `nosniff`; values that only contain those words no longer pass.
