- Make the count collectors and the history store more robust (#766): a history redaction now needs an atomic file exchange and is refused, with nothing changed, where the system has none; appending to a large history file checks it a chunk at a time instead of holding copies in memory; the Instagram activity report, the YouTube geography report and the Threads daily series are only stored when the reply is complete; the insights collectors stop at a source cap, a request budget and a deadline and name what was left out (`budget_exhausted`); a retry after a partly failed write now corrects the day's history value (a small `.numbers.json.pending` note lists run ids only) so history and the numbers file stay in step, for refresh and for import; and a retention policy is checked when it is used. The pending note and history append also hold up against concurrent writers: history append compares a digest of the validated bytes and reads back the new bytes after the write, the pending note carries a nonce and is removed only by its writer, commit detection reads one open numbers file, and a failed attempt that left history untouched takes its id back out of the note (including a write that was rolled back), while a set-aside note that cannot be put back stops the next run until a person looks at it.
