- Fediverse collector slice 2, the Bluesky provider (#922, design in `docs/design/fediverse-collector.md`, epic #244). New `reach_around.counts.bluesky_feed` reads one public account on `public.api.bsky.app` with no login: one `getProfile` call and up to twelve `getAuthorFeed` pages. The whole run shares one budget of 13 HTTP requests (a retry or a redirect hop draws on it like any other request) and one absolute monotonic deadline of 90 seconds that covers the pauses between calls, the retry waits and every request's own timeout; a cursor is checked and never followed from a response, and a cursor seen earlier in the run stops the walk as incomplete. The account's own posts of the 30 days ending at the run instant, by the server's `indexedAt` and never the author-supplied `createdAt`, become rows of three whole numbers (reposts, likes, replies); reposts of other accounts, replies to others, other authors and pinned posts older than the window are not counted. The feed's order is not trusted, so nothing ends the walk early: it stops only at the end of the cursor chain (the read is complete) or at the request, page or time budget while a next cursor still exists (the read is incomplete, `page_cap` or `timeout`, and keeps the prior rows). A feed entry that cannot be read is never treated as absence: no author or a malformed one, a `reason` that is present but not a known repost or pin value (including a null or non-object one), a bad time or a bad count ends the read as incomplete with `bad_shape`. A response that arrives after the absolute deadline is discarded and the read ends as `timeout`. A snapshot is anonymous: it holds the counts, a date, a flag and a fixed reason word, and no actor, handle, DID, link, id, text or time (which account it belongs to is config; `entry_from_snapshot` takes the actor from config to build the re-check link). A read that cannot finish returns a fixed reason word (`partial_pages`, `page_cap`, `rate_limited`, `needs_token`, `account_not_found`, `clock_skew`, `bad_shape`, `timeout`, and the others on the closed list) and keeps the prior rows; a zero is only a finished empty window. The actor is validated strictly (a handle of dot-joined letter, digit and hyphen labels, or a `did:plc:` or `did:web:` id). Also added: `fetch_json_view` (the object twin of `fetch_json_array`, with the same strict numbers and header view), the guard pass over the snapshot (recursive over every key and leaf at any depth, then an exact schema and a consistency table: a complete snapshot has its rows and no reason, an incomplete one has a closed reason and either no rows or its non-empty prior rows, and every other combination is refused, also by `entry_from_snapshot` and `snapshot_aggregates`; a hit writes nothing), the window sums for the history store (`posts_30d`, `boosts_30d`, `favorites_30d`, `replies_30d`, complete reads only) and `entry_from_snapshot`, which turns a fresh complete snapshot into the same `FediverseEntry` the hand-kept `kit.fediverse` block takes; the hand-kept path is unchanged and the loader wiring is slice 4. No egress change: `public.api.bsky.app` was already on the list. A `did:web` id is accepted in its full form (a percent-encoded port and path segments) for the profile and every author, compared exactly; a post that appears twice in a run records the larger value of each count; a `reply` key that is present but null or not an object ends the read as `bad_shape`; and an account with more than about 600 feed entries in its 30-day window reports `page_cap` (incomplete, prior values kept) by design, documented in `docs/kit.md`; a feed post whose `record` is missing or not an object ends the read as `bad_shape` (no evidence it is an original post); a `did:web` host must be dot-joined DNS labels of 1 to 63 characters (no empty label, no hyphen at either end, a dot unless `localhost`) with a port of 1 to 65535 and no leading zero; and a snapshot date must be a real calendar day; a `reply` object (on the entry or on the record) only counts as a skipped reply when it has a root and a parent that each carry a well formed `at://` uri and a cid (an entry's blocked or not-found parent has no cid), and any other reply object, including `{}`, ends the read as `bad_shape`; and a counted post's uri must be an `at://` uri whose authority is the profile DID, whose collection is `app.bsky.feed.post` and whose record key is a short plain string, so a missing, malformed or foreign uri ends the read as `bad_shape` instead of keying and merging distinct posts; and a `did:plc` id must be exactly `did:plc:` plus 24 lowercase base32 characters (`a` to `z`, `2` to `7`) wherever a DID is read (the actor, the profile, every author and every uri authority), so a malformed one ends the read as `bad_shape` and never becomes a verified zero or a clean foreign-author skip. Hermetic tests only.
