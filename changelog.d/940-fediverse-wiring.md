- Fediverse collector slice 4, the wiring (#940, design in `docs/design/fediverse-collector.md`, epic #244). New config `numbers.fediverse` lists at most one Bluesky and one Mastodon-API account (`kind`, `actor` or `host` and `acct`, optional `account_id`), each checked by its provider's own validator, with no token and no unknown keys. `counts refresh` now runs the two providers once a day with the injected clock, transport and sleep: a source read in full passes the snapshot guard, is stored in `numbers.fediverse.json` beside the numbers file and appends one aggregate `api` history row per metric (`posts_30d`, `boosts_30d`, `favorites_30d`, `replies_30d`, whole numbers only); a source that is not read in full keeps its stored snapshot and the history untouched, never writes a zero, and is named in the status file by a fixed reason word. `build`, `kit pdf` and `kit private-measures` feed `kit.fediverse` from a fresh complete snapshot (labeled API, medians still worked out by the build); the hand-kept entry stays in place when there is no source, no file, a damaged or old snapshot, or an incomplete read. New command `counts egress-check` (no network) fails when a configured host is missing from a workflow's allowed-endpoints list. Documentation in `docs/config.md` and `docs/kit.md`; `docs/site.schema.json` regenerated, now with `minItems`, `uniqueItems` and length and character limits for the new source keys (the runtime-only checks are listed in `docs/config.md`). A refresh that reads a snapshot is one unit with one commit point: the snapshot is staged first, the status says `committed: false`, and the rename of the snapshot into place is the commit; the fediverse history rows are derived from the committed snapshot and written after it, then the numbers file, and the status says `committed: true` last. Every run starts by repairing what a crash left: it removes leftover staged and temp snapshot files, appends the rows a crash left out (never twice) and puts `committed: false` in a status that lags a crash; it never says `true` while an earlier attempt's pending note is live. History keeps one row set per platform, metric and day and is never rewritten: a same-day run whose values differ from that day's rows keeps the stored snapshot and reports the platform as skipped with the word `same_day_kept`. The `account_id` schema entry now bounds the integer form too (0 to 99999999999999999999). The instance template's refresh script does not carry `numbers.fediverse.json` yet; that needs a workflow change and is tracked separately.
