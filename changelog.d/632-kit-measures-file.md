- Kit v2 slice 7, the owner-only measures file (#632, epic #244): new `reach-around kit measures --config --site-out --gated-out --out-dir` writes `kit-measures.json`, the public and gated measures the kit shows, each with its trust label, date and period, for the sponsor page and quote to read (and nothing else for a measure value). It is never published: it goes to an owner-only directory outside the site output, the gated directory, the config directory and any git work tree, is mode 0600, and its name is in no published artifact (a test walks both output trees). The build now also writes `kit-binding.json` in the gated directory (digests of the policy, the resolved measures and both kit pages), and `kit measures` refuses unless the config, numbers and both directories match that one build. Private values (whole numbers, decimals, negatives, imported values and free text) are checked as decoded values against an inventory of the private sources before anything is written, numbers by magnitude in any common written form (separators, fullwidth digits, invisible characters), short figures only when written with a unit, and a hit names the field, never the value. The output directory is opened component by component from the root and kept open through the write, and is checked again just before and after the rename so a directory moved meanwhile keeps nothing (the private PDF uses the same code); a directory that holds a git work tree below it is refused. A kit with no measures writes no file. The schema is versioned (`schema_version` 1) and documented in `docs/kit.md`; `load_measures_file` is the one strict reader and checks the type and format of every field. The kit still computes no price. Tests: `tests/test_kit_measures_file.py`, `tests/test_kit_pdf_output.py`.
