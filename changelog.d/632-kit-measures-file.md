- Kit v2 slice 7, the owner-only measures file (#632, epic #244): new `reach-around kit private-measures --config --site-out --gated-out --out-dir` writes `kit-measures.json`, the public and gated measures the kit shows, each with its trust label, date and period, for the sponsor page and quote to read (and nothing else for a measure value). It is never published: it goes to an owner-only directory outside the site output, the gated directory, the config directory and any git work tree, is mode 0600, and its name is in no published artifact (a test walks both output trees). The build now also writes `kit-binding.json` in the gated directory (digests of the policy, the resolved measures and both kit pages), and `kit private-measures` refuses unless the config, numbers and both directories match that one build. Private values (whole numbers, decimals, negatives, imported values and free text) are checked as decoded values against an inventory of the private sources before anything is written, numbers by magnitude in any common written form (separators, fullwidth digits, invisible characters), numbers of 6 or more digits also with every separator removed (a deliberate fail-closed rule: an unrelated pair such as "123, 456" can stop a build, and the error says to reword), short figures when written with a unit or as a measure row with a unit, and a hit names the field, never the value. The output directory is opened component by component from the root and kept open through the write, and is checked again just before and after the rename (the private PDF uses the same code); it warns when the parent folder can be written by the group or others, and the docs say what a path check cannot see and that private output belongs in a folder only the owner can write; a directory that holds a git work tree below it is refused. A kit with no measures writes no file. The schema is versioned (`schema_version` 1) and documented in `docs/kit.md`; `load_measures_file` is the one strict reader and checks the type and format of every field. The kit still computes no price. Review round 1 fixes: `load_measures_file` now recomputes the digest of the rows it loads and refuses a row edited after the build even with a genuine binding; a private decimal is also found written with a decimal comma, spaced punctuation, other scripts' digits or scientific notation; a kit with public measures only now gets a binding with a null gated page and can produce the file (the gated directory must then hold no page); and every directory above the output folder's parent must belong to you or root and not be group or other writable unless sticky, or the write is refused. Tests: `tests/test_kit_measures_file.py`, `tests/test_kit_pdf_output.py`. Review round 2 fixes: a private figure shown as the value of a measure row (a percent row stores tenths, so 123 is 12.3%) is now found, decimals and long numbers included; more written forms of a decimal are found (superscript exponents, a spaced mantissa, other multiplication signs, the Arabic decimal and thousands separators, regional grouping, a middle dot or apostrophe as the point), and the docs now name what is not read (words, fractions, Roman numerals, other bases); the row-validation tests re-digest the rows so each fails when its own check is removed (#632).
Review round 3 fixes: the immediate parent of the output folder now follows the same rule as every directory above it, so a parent the group or others can write (renaming a folder is allowed by its parent's permissions, not its own) or that another user owns is refused, not only warned about, unless it is sticky like `/tmp` (the output folder is owner-only, so a sticky parent protects it); `OutputWarning` is gone. The reader no longer echoes attacker-controlled JSON keys whole: a duplicate or unexpected key is shown as a short ASCII-escaped prefix, at most 5 keys with a count of the rest (#632). Review round 4 fix: the binding stored in the measures file is only a claim (an editor can recompute it), so the reader's `expected_binding` is now required with no default and consumers use `load_measures_for_build(path, gated_dir)`, which takes the expected binding from the build's own `kit-binding.json` in the gated directory and fails closed when it is missing, linked or malformed; a forged file whose rows and own binding were both recomputed is refused, and the docs state what this does and does not defend against (no key: same-user threat model) (#632). Review round 5 fixes: `O_NOFOLLOW` covers only the last name, so a linked gated directory or ancestor could point the binding read at another directory; the binding record, the measures file and the two kit pages are now read through one anchored reader (`read_anchored`: a descriptor-held walk from `/` with `O_DIRECTORY | O_NOFOLLOW` per component, each directory owned by you or root and not group or other writable unless sticky, the file opened `O_NOFOLLOW | O_NONBLOCK` and required to be a regular file before any read, size bounded), so a link anywhere on the path, a swap after the check and a FIFO as the record are refused without blocking (#632).
Review round 6 fixes: the gated page, its policy record and the binding are now committed as one recoverable set (#632). Every new file is written and synced to a temporary name first, the previous files are hard-linked as backups, `.kit-commit.pending` is written, the files are renamed into place with the binding last, and the marker is removed after the binding; any failure rolls every step back from the backups (a rebuild that fails no longer leaves a mix of old and new files, or erases the previous gated deployment), and a crash that cannot roll back leaves the marker, which the measures file, `load_measures_for_build` and the private PDF refuse until the next build rewrites all three files and removes the leftovers (a failure after each step is tested). Builds hold an exclusive `flock` on `.kit-gated.lock` in the gated directory from staging to the end of the commit; the measures file, its reader and the private PDF hold it shared while they check and read, so a build cannot add a gated page between the "no gated page" check and the write, and two concurrent builds do not interleave (the wait is bounded at 30 seconds, then it refuses). The "no gated page" check now looks the name up through the held directory chain instead of by path. The lock is advisory: it orders this tool's own processes and does not stop another user who can write the directory. The anchored reader now also requires the opened file to belong to you or root, to have no group or other write bit and to have one link, since a sticky world-writable directory lets another user plant a same-named file. The policy record and binding are always written or removed together with the page. Tests: `tests/test_kit_gated_commit.py`.
Review round 7 fixes: the gated commit now syncs the directory after the marker and the backups exist and before the first target is renamed (a crash could otherwise keep a renamed page while the marker and the backups were lost, and the readers accepted the new page beside the old binding), after the renames, and after each removal; the backups are removed, and that synced, before the marker, so a crash in the tail leaves the marker (readers refuse) and never private backups under a clean-looking directory; a rollback syncs the restored files before it removes the marker; and every reader now also refuses a gated directory that holds a leftover temporary or backup name of a gated file, which the next build removes (#632). Tests (each reverted to prove it fails): a model of a disk that loses unsynced directory changes (only the page rename may survive) crashes the commit after each of the nine steps and requires the old whole set or a refusal, the directory-sync order is recorded against the renames, leftover names are refused and removed, and a failure after the set is complete keeps the new set and the marker. `tests/test_kit_gated_commit.py`.
