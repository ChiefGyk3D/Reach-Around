- `reach-around leads delete` now clears the short-lived alert hash table as part of an erasure (#905, epic #776). `--yes` requires `--alerts-database NAME`, `--alerts-database-id UUID` and `--leads-database-id UUID` (the `database_id` values from the Worker's own configuration) and fails closed (exit 2, no SQL printed) without them. Before it prints the lead SQL it asks Cloudflare for the id behind each name and refuses unless it equals the id you gave (so a decoy database with the right tables is refused), then reads both schemas, and refuses a database that lacks the `alert_dedup` table or that holds the lead tables without being the leads database. That first step exits 10: the checks passed and nothing is erased. After you apply the lead SQL, `--finish` repeats the checks, reads the lead tables back, checks again, clears the whole alert table with one statement that deletes only while the alert database holds no lead table, reads it back as 0, waits and reads it back again, checks the ids and schemas a last time, and names any row whose life began after the erasure started. Exit 0 from `--finish` is the only completed result (a dry run also exits 0 but requests nothing); exit 3 means the lead rows are erased but the alert hashes are not confirmed cleared or a database changed during the run; exit 4 means the lead rows are not confirmed erased. The tool runs only the wrangler installed in this repository (`--wrangler PATH` must stay inside `worker/node_modules`; never `PATH` or `npx`): the real path must stay inside the wrangler package, the package files and npm's install record must match `worker/package-lock.json`, and the file and every directory above it must be unwritable by others. This is a trust boundary, not an integrity check: it hands your token to that program, never asks it for a version, and cannot prove the installed files are the published ones. It passes only the token, the account id, `HOME` and a fixed `PATH`, runs in `/` with no shell and no stdin, and reads output with a hard size cap. The erasure guard test now records the statements the real `--finish` flow runs and judges them on the seeded schema, and the `alert_dedup` known gap is removed from `scripts/erasure-stores.json`. `docs/privacy.md`, `docs/alerts.md`, the checklist and the command help describe the steps, the exit codes and the remaining window (keep the kit gate closed while you erase). The test suite can no longer start a real wrangler, node, npm or npx from any code path.
