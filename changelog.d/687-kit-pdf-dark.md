- Kit PDF theme (#687, epic #244, decision D9): both kit PDFs now print dark, matching the screen. The print sheet drops the white paper, black text and blue links and reads the screen's own tokens instead (`--ra-color-bg`, `--ra-color-text`, `--ra-color-link`, `--ra-brand-gray` for table rules), with `color-scheme: dark` forced and the dark background on the page margins too. No color is invented. The renderer command line is unchanged: instead of a print-background flag the sheet sets `print-color-adjust: exact`, which makes Chromium paint the dark fills. Text stays real, selectable text, so the PDF text check and the private-figure needles work as before; the policy-record refusal and the wall are untouched. New tests (`tests/test_kit_pdf_dark.py`) measure body, muted and link contrast from the real token values (4.5:1 for text, 3:1 for table rules), assert no literal color in the sheet, and, with `--run-visual`, render with Chromium and read the page pixels.
