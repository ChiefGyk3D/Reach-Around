- Fediverse collector slice 1, the shared plumbing (#921, design in `docs/design/fediverse-collector.md`, epic #244). New `fetch_json_array` beside `fetch_json` returns a top-level JSON array with a read-only view of a few response headers (`Link`, `Retry-After`, `Date`, rate-limit headers), under a hard 1 MiB cap, with the same https, host, redirect and fixed-error-word rules; `fetch_json` is unchanged. New pure 30 day window helper (server-assigned `created_at` or `indexedAt` only, clock passed in), the aggregate-only `{boosts, favorites, replies}` row with a `NotProvided` marker so an incomplete read keeps the prior values and is never a zero, and a hand-run probe `scripts/fediverse-probe.py` that prints status codes, header names and counts only and is not run by CI. Hardening after review: `keep_prior` accepts only exact `InteractionRow` values and rejects a whole read with one bad row (`bad_shape`); the reason list is closed, including the `egress_*` words; a missing or unreadable server `Date` is treated as an untrusted clock; the array path (`fetch_json_array`) alone refuses `NaN`, `Infinity`, overflowing numbers and integers over 18 digits, while the shared object path keeps accepting numbers exactly as before; response header names are matched case-insensitively and a doubled name is dropped; unexpected transport failures map to one fixed word; the probe prints only allowlisted header names plus a count of the others; and the check that the probe is never run by CI covers `.yml` and `.yaml` workflows, composite actions, task-runner files and glob or `python -m` indirection. Second hardening round: the fixed-word fetch errors are raised after the handler is left, so they carry no chained original exception (no `__context__` or `__cause__`); on the array path the integer limit is exactly 18 digits not counting a minus sign (`MAX_INT_DIGITS`), so a 19-digit id is refused there by design and a provider that needs larger ids reads them as strings (`fetch_json` still accepts 19-digit integers such as TikTok cursors); and the probe refuses to start against the real network when a CI marker is set unless the owner override is given, with the static check also covering `find` piped to `xargs`. No provider and no live host yet; the Bluesky and Mastodon providers are #922 and #923.
