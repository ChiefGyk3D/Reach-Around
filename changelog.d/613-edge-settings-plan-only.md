- Edge settings as code (#613, epic #246): `deploy/edge/` holds an OpenTofu module (Cloudflare provider locked, direct install only) and `desired-state.json` for the zone-wide AI crawler policy, the managed `robots.txt` and Bot Fight Mode (deferred, off). The module could change the zone if run by hand with a write token, so that is prohibited by policy: only a read-only token is issued, no workflow holds a credential, and the offline check fails if the folder holds anything but the one reviewed resource, bound exactly to the desired state, or any unexpected file such as a saved plan. The one rate rule on the beacon token path `/e/t` (4 requests per 10 seconds per client IP and edge location) is a documented manual step the live check only reports. No script in the repository passes an API token to a program: the plan runs only inside the project's infrastructure pipeline with its own binary and credentials, and the offline check fails if `deploy/edge/` holds a launcher, a CLI configuration or any text that names a token variable or starts a subprocess. `scripts/check-edge.py` has an offline mode (CI) and a live read-only mode that validates the desired state first, with a validated `--site-host`, pinned addresses, no redirects, no proxy or CA overrides and a hard 30 second limit on the robots.txt fetch (at most 3 addresses). The zone is shared with staging, so every setting reaches both. Docs: `docs/edge.md`. `tests/test_edge_settings.py` covers it with negative cases. The offline check reads the `.tf` files with a small tokenizer, not brace counts per line: a brace inside a string, an interpolation, a second block on one line, a lone carriage return or anything it cannot parse fails closed, and the `terraform` and `variable` blocks are checked against an attribute allowlist. The offline check also requires every reviewed file to exist and exactly one `zone_id` variable; the OpenTofu minimum, the provider manifest identity and the lock entry shape are validated exactly; a rate rule matched by reference and another matched by expression are reported as ambiguous. The offline check also fails when any file outside the checker, of any suffix, depth or encoding, names the read token variable (documentation excepted; the test file only inside fixture strings). The checker refuses to run unless the interpreter is isolated (`python3 -I`), before it reads the token. The live check refuses TLS key log and related TLS debug variables, disables key logging in its own context, reports any unexpected field on the live rate rule as a difference, and writes a snapshot through a temp file and an atomic link so a failed write leaves nothing behind, and a failure to remove the temp name after the snapshot is installed is a warning, not a failed save.
