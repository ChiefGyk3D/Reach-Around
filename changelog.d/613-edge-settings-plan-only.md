- Edge settings as code (#613, epic #246): `deploy/edge/` holds an OpenTofu module (Cloudflare provider locked, direct install only) and `desired-state.json` for the zone-wide AI crawler policy, the managed `robots.txt` and Bot Fight Mode (deferred, off). The module could change the zone if run by hand with a write token, so that is prohibited by policy: only a read-only token is issued, no workflow holds a credential, and the offline check fails if the folder holds anything but the one reviewed resource, bound exactly to the desired state, or any unexpected file such as a saved plan. The one rate rule on the beacon token path `/e/t` (4 requests per 10 seconds per client IP and edge location) is a documented manual step the live check only reports. `deploy/edge/plan.sh` runs `tofu plan` only, under a scrubbed environment with the token passed by file descriptor, and refuses a tofu binary or directory that the group or others can write. `scripts/check-edge.py` has an offline mode (CI) and a live read-only mode that validates the desired state first, with a validated `--site-host`, pinned addresses, no redirects and no proxy or CA overrides. The zone is shared with staging, so every setting reaches both. Docs: `docs/edge.md`. `tests/test_edge_settings.py` covers it with negative cases. The offline check reads the `.tf` files with a small tokenizer, not brace counts per line: a brace inside a string, an interpolation, a second block on one line, a lone carriage return or anything it cannot parse fails closed, and the `terraform` and `variable` blocks are checked against an attribute allowlist.
