- Instance template deploys through the reusable Worker workflow (#694, epic #246): `examples/instance-repo/.github/workflows/deploy.yml` no longer runs the Worker deploy inline or reads a `CLOUDFLARE_API_TOKEN` GitHub secret. It has two tiers, `staging` and `production`, each its own environment and its own secret-manager identity (OIDC, one identity per tier; config `dev` for staging, `prd` for production). `worker-<tier>` calls `ChiefGyk3D/Reach-Around/.github/workflows/deploy-worker.yml` pinned to the commit in `engine.lock` (with `# v0.3.0-rc.6`); `pages-<tier>` publishes the site, with the token as one masked output mapped into the publish step only. Staging runs on a push to `main` or by hand with target `staging`, only while `ALLOW_STAGING_DEPLOY` is exactly `true`. Production runs only by hand on `main` with target `production` and only while the repository variable `ALLOW_PRODUCTION_DEPLOY` is exactly `true` (absent by default, so production is off). `id-token: write` is held only by the four deploy jobs. The `validate` job now hands the engine pin to the others and fails when the two Worker names are equal, are not plain names, or are the engine's test Worker. The template's `engine.lock` moves to `0.3.0-rc.6` (image digest read from the registry), Renovate groups the two call pins with it, and the template test accepts a pre-release version comment (`-rc.N`, `-alpha`, `-beta`; a bad suffix still fails). New tests keep the call pin equal to `engine.lock`, all shared-repository pins on one commit, the caller permissions at least what the called workflow declares, no `secrets` anywhere in `deploy.yml`, production unreachable from a push, and `id-token: write` on the four deploy jobs only. Docs: the template `README.md` (environments, repository variables for both tiers, `ALLOW_PRODUCTION_DEPLOY`), `docs/instance-repos.md`, `docs/deploy.md`. Existing instance repositories: nothing changes until you copy the new workflow and set the variables; the old repository secret for the Cloudflare token and the variables `PAGES_PROJECT`, `D1_DATABASE_ID`, `RATELIMIT_NAMESPACE_ID`, `SITE_HOST` and `ZONE_NAME` are no longer read.
  - Instance template deploy hardening after review (#694): staging now runs only while the repository variable `ALLOW_STAGING_DEPLOY` is exactly `true`, and the README and `docs/instance-repos.md` say to create and protect both environments (reviewer, **Prevent self-review**, `main`-only) before the first push and to set that variable last, because GitHub creates a missing environment unprotected on first use. `validate` fails when `STAGING_PAGES_PROJECT` equals `PRODUCTION_PAGES_PROJECT` (lowercased, whole value), and the staging Pages job refuses the production project. The README no longer suggests the operator be their own reviewer; it says what environment protection can and cannot guarantee for a sole owner. The permission test now reads the callee's permissions recorded for the pinned commit (`tests/fixtures/instance_template/callee_permissions.json`), checked against the pin in `engine.lock` and, when the pinned commit is in the clone, against the workflow at that commit.
  - Instance template review wording and callee check (#694): the README and `docs/instance-repos.md` no longer offer a second login as independent approval. They say independent approval needs a second human, that environment protection and **Prevent self-review** do not establish that the approver did not author the commit, and that "not the author" must be enforced by protected-branch pull-request review or an external policy in addition. A sole owner's approval is described as a confirmation pause only. The caller/callee permission test now reads the callee's permissions straight from `git show <ENGINE_REF>:.github/workflows/deploy-worker.yml`, fetching the commit when the checkout lacks it; a missing commit fails the test when the `CI` variable is set and skips with a message otherwise. The committed fixture is only a review aid that must equal those permissions. A new test shows a newly required callee permission (`packages: read`) fails the compatibility check.
