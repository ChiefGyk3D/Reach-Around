- Kit v2 slice 3, the measure model, the registry and the compile shim (#628, epic #244): every number the kit prints is now a measure (one value, one unit, one date, one trust label), compiled once from `kit.metrics`, `kit.analytics` and `kit.engagement`; the pages read measures only and no renderer code path reads an old field (a test walks the renderer functions and fails on one). Pages for every existing config build byte for byte as before (the goldens are unchanged), with one exception: a typed 30-day change that rounds to zero prints `+0.0%`, where a tiny negative one printed `-0.0%`. A measure is never visible to a wider audience than the field it came from, so engagement figures stay on the gated page. New `kit.sections` (public; at most 20): one platform card each, with `account`, `show` (`default` or registry keys in print order), `headline` and `hide_if_empty`. A configured platform with no number to show prints "No numbers yet" (nothing with `hide_if_empty`); a key with no value is left out, never zeroed; Twitch and Kick share one default set and the same markup. The registry holds definition text, unit, default audience and formula per key, and `docs/kit.md` lists each one. Both PDFs print the cards and their text check expects each card.
