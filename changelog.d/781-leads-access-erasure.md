- Lead access and erasure tooling (#781): new `reach-around leads show --input EXPORT --email-file PATH|-` prints what an access request needs for one address from a local export (masked address, country, created and verified times in UTC, kit event kinds with their hours) and nothing else: no id, no other lead, no SQL, no network call, no file written. The address comes from a file or stdin; `--email` is refused with a fixed message and never echoed. The export is checked as strictly as for `leads delete` (every column named, event kinds and hour timestamps validated, a failed wrangler block refused). New `reach-around leads delete --checklist` prints every copy to clear besides the database rows (alert copies, inquiry text, D1 Time Travel 7 days Free or 30 Paid, hand-made exports, shell history) and takes no export or address. The lead commands act on the leads database only: they print `database: reach-around-leads`, accept `--database NAME` with a name that contains `leads` and refuse any other (so an analytics export is refused), and `leads delete --yes` prints the exact `wrangler d1 execute reach-around-leads` apply command. Lead rows must have exactly the five selected columns, a lead id that appears twice refuses the export, event times that are not on the hour are shown as their hour, and error messages no longer carry the masked address. `docs/privacy.md` gains "Access and erasure requests (GDPR)": the one-month response rule and the Art. 11 position for raw view rows; visitor-facing notice sentences are marked TODO-copy.
