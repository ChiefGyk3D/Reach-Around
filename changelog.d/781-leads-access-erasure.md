- Lead access and erasure tooling (#781): new `reach-around leads show --input EXPORT --email-file PATH|-` prints what an access request needs for one address from a local export (masked address, country, created and verified times in UTC, kit event kinds with their hours) and nothing else: no id, no other lead, no SQL, no network call, no file written. The address comes from a file or stdin; `--email` is refused with a fixed message and never echoed. The export is checked as strictly as for `leads delete` (every column named, event kinds and hour timestamps validated, a failed wrangler block refused). New `reach-around leads delete --checklist` prints every copy to clear besides the database rows (alert copies, inquiry text, D1 Time Travel 7 days Free or 30 Paid, hand-made exports, shell history) and takes no export or address. The lead commands act on the leads database only: they print `database: reach-around-leads`, require `--database reach-around-leads` (the owner's statement of where the export came from, not proof: the export carries no database identity), `leads delete` also refuses an export in which a lead id appears twice, prints no form of the address to stderr on success, refuses the address on the command line (only `--email -`), builds SQL in which every deleting statement pairs the lead id with its address so a forged or stale export deletes nothing, removes events that arrive between the two deletes, and ends in a read-back of both tables (0 and 0 means no remaining rows at that moment, not proof of completed erasure: D1 has no transaction in a file and an event can arrive after the read, so the file is run again until two consecutive runs read 0 and 0), writes the SQL with `--sql-out` (a new file, mode 0600, refused if the path exists or its last component is a symlink, partial file removed on a failed write, the printed apply command shell-quoted), refuses an access export that lacks the kit events result, prints a checklist that claims only what it checks and lists the places to check by hand, and `leads delete --yes` prints the exact `wrangler d1 execute reach-around-leads` apply command. Lead rows must have exactly the five selected columns, a lead id that appears twice refuses the export, event times that are not on the hour are shown as their hour, and error messages no longer carry the masked address. `docs/privacy.md` gains "Access and erasure requests (GDPR)": the one-month response rule and the Art. 11 position for raw view rows; visitor-facing notice sentences are marked TODO-copy.
