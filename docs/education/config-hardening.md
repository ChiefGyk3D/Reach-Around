# Why the config loader says no

Reach-Around reads a YAML file that a person wrote. That sounds harmless, but
the file is input, and input is where trouble starts. A config might be pasted
from a forum, generated by a script, or edited by someone in a hurry. The
loader (`src/reach_around/config/loader.py`) and the models
(`src/reach_around/config/models.py`) are strict on purpose. When they refuse
something, they say which file and which line, so the fix is easy.

The field-by-field reference is in [../config.md](../config.md). This page
explains the reasons. Each rule names the test that proves it. The tests live
in `tests/config/test_loader.py` and `tests/config/test_models.py`.

## The file itself

**Duplicate keys.** If a file says `title: A` and later `title: B` in the same
mapping, most YAML readers quietly keep the last one. The first line looks
live but does nothing. That is how a reviewer approves one value and the site
ships another. The loader refuses it and names the line.
Proof: `test_duplicate_key_refused`.

**Anchors, aliases and merge keys.** An anchor (`&a`) names a chunk of YAML;
an alias (`*a`) pastes it elsewhere; a merge key (`<<`) blends one mapping
into another. They are handy, and they hide what a value really is, since you
must chase references to read the file. Worse, aliases can nest: a few short
lines can expand into billions of items, called an alias bomb, which eats all
memory. The loader checks parser events before anything is built, so it stops
at the first anchor or alias and never expands anything. A config this small
does not need them, so they are all refused.
Proof: `test_anchor_refused`, `test_alias_refused`,
`test_anchor_and_alias_pair_refused`, `test_merge_key_refused`,
`test_alias_bomb_refused_before_expansion`,
`test_alias_bomb_without_anchors_is_refused_as_alias`.

**Odd tags.** A tag like `!!python/object:os.system` tells some YAML readers
to build arbitrary program objects. That has led to real remote-code
execution bugs in other projects. The loader only builds plain data (text,
numbers, booleans, dates, lists, mappings), and any other tag is an error.
Proof: `test_python_tag_refused`, `test_unknown_tag_refused`.

**Huge files.** A multi-gigabyte "config" can exhaust memory before a single
rule is checked. The limit is 1 MiB, checked from the file size and again
while reading, since a file can grow between the two.
Proof: `test_oversized_file_refused`; `test_file_at_size_limit_loads` shows the
limit is exact, not too tight.

**Deep nesting.** Lists inside lists inside lists, thousands deep, can crash a
parser with a stack overflow. The limit is 64 levels, and even a much deeper
file ends as a clean config error, never a crash.
Proof: `test_deep_nesting_refused`, `test_nesting_at_limit_loads`,
`test_very_deep_nesting_is_a_config_error_not_recursion`.

**Symlinks and odd files.** If the path is a symlink, it could point at a
file you never meant to read, and what you review may not be what is loaded.
The loader opens the path with `O_NOFOLLOW`, so a symlink is refused; give the
real path instead. It also refuses anything that is not a regular file, such
as a directory or a pipe, which could block forever.
Proof: `test_symlink_refused`, `test_directory_refused`,
`test_missing_file_refused`.

**Encoding, empty files, extra documents.** Invalid UTF-8, an empty file, a
comment-only file and a file with several `---` documents each have no single
clear meaning, so each is refused.
Proof: `test_invalid_utf8_refused`, `test_empty_file_refused`,
`test_comment_only_file_refused`, `test_multiple_documents_refused`.

## The values

**Unknown keys.** Every model forbids keys it does not know, so a typo like
`affilate: true` fails loudly instead of quietly turning the disclosure off.
Proof: `test_unknown_keys_refused`.

**URLs are https only.** A link on a page is something a visitor clicks.
`javascript:alert(1)` would run script in the visitor's browser, and
`data:text/html,...` can carry a whole fake page. Plain `http://` can be read
or altered on the way. So only `https` is accepted, with a host name.
Proof: `test_https_urls_only` (covers `javascript:`, `data:`, `http://` and
`//example.com`).

**No credentials or control characters in URLs.** `https://user:pass@host/`
puts a password in a file that gets committed and published, and the
`user@` trick makes `https://trusted.example@evil.example/` look like it goes
somewhere it does not. Spaces and control characters (newlines, null bytes)
are refused too, since they can confuse tools that process the URL later.
Overlong URLs (over 2048 characters) are refused.
Proof: `test_url_with_userinfo_or_control_characters_refused`.

**Ids are slugs.** Each id becomes a part of the page: an HTML anchor, a file
or folder name, a key in the click manifest. A slug
(`^[a-z0-9][a-z0-9-]{0,39}$`) cannot hold spaces, slashes or `..`, so an id can
never climb out of its folder or break out of an attribute. Ids must also be
unique across the whole site, so one id always means one thing.
Proof: `test_ids_are_slugs`, `test_slug_of_forty_characters_is_allowed`,
`test_ids_are_unique_across_the_whole_site`, `test_ids_unique_between_tabs`.

**Dates are plain dates.** A bare YAML timestamp is parsed in a time zone the
writer did not pick, which can move a link's start by a day. Date fields take
only `YYYY-MM-DD`, and the site's `timezone` setting decides the day.
Proof: `test_dates_must_be_iso_dates_not_datetimes`,
`test_unquoted_yaml_timestamp_refused`,
`test_show_until_not_before_show_from`.

**HTML in text is not an error.** A title such as `<b>hi</b>` is kept as
written. Safety comes from the page builder escaping text when it renders,
not from guessing which characters are bad.
Proof: `test_html_in_text_is_kept_verbatim_for_the_template_to_escape`.

## The pattern

Each rule closes a door that is easy to leave open. The loader refuses early,
before any other code sees the data. The error names the file and the line.
There is a test for every refusal, and a matching test that the limit allows
exactly what it should.
